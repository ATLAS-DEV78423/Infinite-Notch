# Agent Session Inspector — Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show OpenCode/Hermes commands awaiting approval, file activity, working directory, context usage and session details in Coucou's existing animated interface, without making approval decisions.

**Architecture:** Agent-side adapters emit bounded, sanitized session snapshots through the existing relay. Pure native/web reducers isolate sessions and feed an inspector using existing cards, Mochi and motion; legacy hook behavior remains separate. Qualify upstream APIs and freeze the wire fixtures before parallel implementation.

**Tech Stack:** Swift 6/Foundation/SwiftUI/AppKit; existing Tauri 2/Rust and TypeScript/DOM/CSS; Node built-ins and Python standard library for adapters/tests. No new app framework or runtime dependency.

**Spec:** [Approved session-inspector design](../specs/2026-10-03-agent-session-inspector-design.md).

**Privacy amendment:** User confirmed local display only: minimum necessary fields in temporary memory, no analytics/tracking, disk storage, activity logs or external transmission. Clear affected data when the session ends or monitoring stops, even while Details is open. Earlier post-session retention is removed. Implementation is partial; see the current verification receipt.

**Minimization amendment (latest user ruling):** Collect only the agent label, opaque correlation IDs, live status, explicitly reported cwd, safe path/command previews, passive approval identity, explicitly reported usage counters, and header model/provider labels. Never collect file contents/diffs, prompts/responses/transcripts, inferred/session titles, `final_summary`, subagent summaries/goals/roles, raw error text, credentials, environment/terminal metadata, arbitrary tool output, network metadata, unrelated app state, or broad inventories. Generic enumerated outcomes replace all response summaries, including canonical-hook payloads.

**Replay-safety amendment (2026-10-04):** User permits temporary bounded opaque replay IDs solely to reject delayed updates. Clear all display content immediately. Receiver retirement markers are memory-only, expire after 30 seconds and cap at 64 per agent; marker-cap overflow fails closed rather than evicting protection. Native connection ordering/expiry bounds still require real evidence; this does not automatically solve arbitrary post-expiry delays or initially unseen emitters.

**Qualification gate:** Initial probes found only legacy CLI `1.18.32`. Disposable `2.0.6` baseline plugin/relay checks now pass; Hermes registration/dispatch passes with supplied synthetic kwargs. Full rich runtime qualification and Task 1 remain incomplete. The [draft protocol](../../AGENT_MONITOR_PROTOCOL.md) and invented wire fixtures alone cannot satisfy that gate. Main-task runtime investigation owns it; see [the current receipt](../../research/agent-inspector-verification.md).

## Global Constraints

- Phase 1 is passive; Phase 2 interactive approvals require a separate plan.
- Preserve existing Unix socket/named pipe transports and same-user checks; no new listening service.
- Isolate by agent + emitter + session. One visible pill per agent; session selection lives inside Details.
- Inspector: 640 wide, 280 high, inside the existing 320-high panel. Other view sizes stay unchanged.
- Preserve Mochi/ticker, opening spring response 0.5/damping 0.72 and 0.34 s closing curve on macOS; reuse Tauri motion helpers. Honor reduced motion.
- At most four ordinary live-display renders per second per session; approval/terminal changes are prompt.
- Snapshot maxima: 20 files, 8 tools, 8 approvals, 8 subagents, 20 current-session activity rows; at most 16 live sessions per agent. These are working display buffers, not archived activity.
- UTF-8 limits: names/IDs 256 bytes, paths 1,024, safe command previews 1,000; wire payload at most 64 KiB. IDs are rejected, never truncated.
- No completed-session retention or history. Session end/reset or monitoring stop clears snapshots, content queues, lookups, counters and UI text; Details does not override cleanup. A still-live session may show its latest outcome, not accumulated past turns. Keep the generic 5.2 s finish animation without preserving ended-session content.
- After 30 seconds without updates, show last-update age, not invented disconnect/completion.
- Unknown context/directory/counters remain unknown. Context-window usage is not cumulative tokens; never count overlapping cache/reasoning buckets twice.
- Redact before IPC; never forward raw file bodies/diffs, transcript histories, credentials or unfiltered tool results. All committed fixtures/evidence are invented examples.
- No activity records (even event names or redacted payloads), IDs, paths or usage counters in app/relay/debug logs, persistent stores, clipboard, crash attachments or exports. Audit existing hook logging, not just new code. Use only the same-device relay and local authenticated agent-host APIs; no remote endpoints, analytics SDKs or background reporting.
- No approval replies, policy mutation, installers, global configuration edits or unrelated refactors.
- Work in the current checkout as requested. Preserve prior uncommitted adapters/docs/skill imports. Do not commit `.opencode/` or unrelated files as part of these tasks.
- Git author identity is currently unset: obtain repository-local author identity before commits, or leave changes uncommitted if the user chooses. Never invent it.

## Review Focus

1. Shared OpenCode service with plugins in multiple locations: no duplicate or cross-project observations (Task 3 runtime fixture).
2. Upstream resolves approval while another tool finishes: only the exact request changes; no policy call (Tasks 3–6).
3. Two turns overlap the old 5.2 s removal timer: active session and its details survive (Tasks 5–6 fake-clock replay).
4. Secret-bearing free text, Unicode and very long paths: redaction before byte truncation, visible omission, no executable markup (Tasks 2–6).
5. End/disable/disconnect during a live-display burst or focused Details: clear content without bypassing privacy for UI continuity, preserve unrelated approval ownership (Tasks 2–7).

## Draft wire and reducer decisions (runtime qualification blocked)

Task 1 writes these into `docs/AGENT_MONITOR_PROTOCOL.md`; later tasks consume that draft and fixtures consistently. This fixes intended wire names, not upstream compatibility; runtime qualification remains a gate.

- Envelope: `hook_event_name` (existing canonical name or `AgentDisplayUpdate`), `coucou_agent: "opencode" | "hermes"`, optional `session_id`/`cwd`, and `coucou_monitor`.
- Monitor required fields: `version: 1`, `emitter_id`, positive safe-integer `sequence`, `scope: "session" | "agent"`, `status`, `directory_known: boolean`. Session scope requires an exact `session_id`; agent scope is only for unattributed observations and does not invent a session.
- Status: `idle | thinking | working | awaiting_approval | retrying | ratelimited | compacting | finished | failed | interrupted | ended | unknown`.
- Optional identity: `turn_id`, `parent_session_id`, `model`, `provider`; `capabilities` maps `files/context/approvals/subagents/compaction` to `reported | unavailable`. Absence means unknown. No title field.
- `files`: `{id, tool_call_id?, path, action: read|write|edit|reference, state: pending|running|completed|failed, cwd?}`.
- `tools`: `{id, name, state: pending|running|completed|failed|blocked|cancelled, command?, target?, cwd?, duration_ms?}`; no raw error text.
- `approvals`: `{id, request_id?, tool_call_id?, state: pending|approved|denied|cancelled|unknown, command?, target?, reason?: permission_required|policy|unknown, cwd?}`. `id` is an internal observation ID, not a claimed upstream request ID. No top-level `request_id` or free-text reason.
- `subagents`: `{id, session_id?, state: running|finished|failed|interrupted|unknown, duration_ms?}`; parent identity is the enclosing session. No goals/roles/summaries.
- `activity`: `{id, kind: retry|rate_limit|compaction|error|session_reset, attempt?}`; no text. Optional `outcome: completed|failed|interrupted|incomplete` renders fixed generic wording. No `final_summary`.
- `usage.context`: `{tokens?, limit?, quality: reported|estimated, accounting: includes_cache|excludes_cache|unknown}`. Only compatible whole-input counts may fill the gauge. `usage.totals`: `{scope: session|observed, partial?: boolean, input?, output?, reasoning?, cache_read?, cache_write?, cost_usd?, accounting: includes_cache|excludes_cache|unknown}`; accounting labels the reported cache convention, not a guessed sum.
- `overflow` contains omitted-row/session counts; `truncated_fields` contains field paths. Arrays omitted from a newer full snapshot become empty; unknown scalar fields stay absent, not zero.
- Key session maps by a tuple (JSON tuple string in JS, Hashable struct in Swift), never concatenated ambiguous delimiters. Keep agent-scope observations separate from the 16-session collection.
- Validate before state mutation. Required-field/type/identity/version errors reject the monitor; invalid optional groups are omitted. Absent/invalid monitor uses legacy handling only after the adapter envelope allowlist removes prohibited fields; standalone `AgentDisplayUpdate` is ignored. The no-log rule applies to all OpenCode/Hermes adapter packets even if invalid or legacy. Valid duplicate/stale monitor returns `stale`, skipping accompanying canonical side effects.
- Accepted monitor packets use snapshot-driven lifecycle, not legacy per-agent removal timers. Packet status and approvals drive badges; canonical names are for animation/ticker transitions only once. Reject stale sequence before side effects.
- Shared apply result: `{disposition: "legacy"|"accepted"|"stale"|"ignored", key?: SessionKey, status_changed: boolean}`. No result contains an approval decision.
- Receiver clock is injected milliseconds; producer IDs/sequences are local per instance. No wall-clock ordering across machines. Epoch restart gets a new emitter ID.
- Internal decoded `MonitorPacket` is `{agent, session_id?, cwd?, monitor}` where `monitor` is the validated wire `coucou_monitor`; `MonitorUsage` mirrors `monitor.usage`. JS `Packet` denotes the wire envelope, not `MonitorPacket`. Swift uses matching Codable value types/enums; JavaScript uses string literal unions. This normalization never changes wire names.
- Map monitor statuses to existing BotState: thinking→thinking, working→working, awaiting_approval→approval, retrying/compacting→thinking, ratelimited→ratelimit, failed→error, finished→finished, idle/interrupted/ended/unknown→idle. Pending observed approvals keep an amber badge independent of selection; badge priority approval→error→finished. Retry/compaction wording remains in activity text.
- Full received snapshots still pass a receiver-side allowlist/preview scrub before becoming UI text. Neither producer nor receiver records activity, identifiers, counters or payloads, even redacted. Synthetic secret cases cover password/token/key flags, bearer headers, URL credentials/query values, assignment forms, multiline output and nested input objects; suppress ambiguous previews instead of merely shortening them.
- Bound uncorrelated agent-level observations to eight plus overflow. Limit deduplication to 256 request/tool IDs per session; if older IDs leave that window, stop derived accumulation and label totals partial until authoritative totals arrive, rather than risk double counting. Eviction never mutates unrelated sessions.
- Both stores additionally expose `observations(agent)` returning at most eight `MonitorObservation` values: `{emitter_id, approval: MonitorApproval, received_at_ms}`. `MonitorApproval` mirrors one wire approval row. This powers a separate `Session unavailable` shelf even when no correlated session exists; UI keys combine emitter and observation ID. A new agent-scope snapshot replaces only its emitter's observations before the overall cap is enforced.
- Cleanup: an accepted `status: ended` session snapshot has no content and immediately removes the session. Agent-scope `ended` clears that emitter. `clear(): void` on stores resets all state; producer shutdown cancels reads, discards queues/caches and sends only an empty best-effort clear marker. Paused Coucou drops incoming packets before any display mutation/logging. No open-panel retention exemption.
- Abrupt-loss fallback: content-free `AgentDisplayAlive` at start and every 10 seconds; exact shape and FIFO control ordering are defined in the draft protocol. It contains only version, emitter identity and up to 16 opaque active session IDs. Missing sessions clear; 30 seconds without a valid signal clears the emitter. Before its first signal, first content receipt starts one 30-second grace, never renewed by content. Heartbeats never renew content freshness or resurrect details; late callbacks from an invalidated local generation are dropped. Cap controls at 64 KiB; never log them.
- **Unresolved ordering/cleanup gate:** the existing fire-and-forget transport does not prove FIFO processing across connections. Local generation guards cover already-tagged callbacks, not old packets first received after resume. With cleared sequence state and no tombstones, Tasks 2–7 must demonstrate a bounded ordering/generation design: hold an already-sent packet until after teardown/roster clearing, and separately after pause/clear/resume, then prove it cannot restore details. Ordered fixture playback alone is insufficient; revise the draft controls if required.
